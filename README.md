# sharbel game realtime server

هذه حزمة الخادم الجديد قيد تجهيز النشر. لم يتم نشرها بعد، والتطبيق المنشور 0.5 ما زال يستخدم مسار HTTP القديم. يلزم نشر الخادم وربط عميل اللعبة ببروتوكوله قبل إصدار تحديث للمستخدمين.

الخادم يحسب فيزياء الغرفة 60 مرة في الثانية ويرسل حالتها 20 مرة في الثانية عبر اتصال WebSocket مستمر. الغرف النشطة والأوامر تبقى في ذاكرة عملية الخادم. تحفظ قاعدة بيانات ملفات الأصدقاء المنفصلة بياناتها كما في الإصدار السابق.

## التشغيل

تحتاج Node.js 22 أو أحدث.

```sh
npm ci
npm test
npm start
```

يستمع الخادم إلى `0.0.0.0` وعلى قيمة `PORT` التي تحددها الاستضافة، أو 8080 محلياً. فحص الصحة `GET /health`. اتصال اللعبة `/ws`.

لبناء Docker من مجلد الحزمة

```sh
docker build -t sharbel-realtime .
docker run --rm -p 8080:8080 sharbel-realtime
```

## النشر

شغّل **نسخة واحدة** من الخادم على استضافة دائمة تدعم WebSocket واتصالات WSS المشفّرة. عند استخدام Node مباشرة يكون أمر البناء `npm ci` وأمر التشغيل `npm start`. يمكن للاستضافة إنهاء TLS ثم توجيه الاتصالات إلى منفذ الخادم. لا تضف مفاتيح خاصة إلى الحزمة.

الغرف تنتهي عند إعادة تشغيل عملية الخادم. انقطاع اتصال اللاعب مؤقتاً يسمح باستعادة نفس الجلسة بكود الغرفة ورمزها الخاص لمدة 30 ثانية. تُمسح أوامر الحركة المعلقة عند فصل الاتصال، ويمكن استئناف نفس الجولة عند العودة خلال المهلة.

## بروتوكول عميل التطبيق

يرسل العميل JSON عبر WSS إلى `/ws`.

1. إنشاء غرفة برسالة `{type:"create",requestId:"unique-id",name,level}` أو الانضمام برسالة `{type:"join",requestId:"unique-id",code,name}`.
2. تحفظ نتيجة الجلسة `code, token, playerId`. رمز `token` خاص باللاعب ولا يظهر في لقطات حالة الغرفة. استعادة الاتصال برسالة `{type:"resume",requestId:"unique-id",code,token}`.
3. صاحب الغرفة يرسل `{type:"action",requestId:"new-unique-id",action:"start"}`. تتوفر كذلك `next` و`restart`.
4. لكل إطار محلي يجهز العميل `{seq,tick,axis,jump}` ويرسلها دفعات لا تتجاوز 12 أمراً برسالة `{type:"input",round,commands}`. `seq` يتزايد لكل لاعب و`tick` هو إطار الغرفة، و`axis` إحدى القيم -1 أو 0 أو 1. يجب أن تكون الأوامر في ترتيب زمني.
5. تحتوي رسائل `state` على `round,tick,ack,accepted,controls,world` وهوية اللاعب. يحتفظ العميل بتاريخ المدخلات غير المؤكدة، ويعيد تشغيل المدخلات بعد لقطة الخادم عند التصحيح، مع مراعاة إطار اللقطة وأوامر التغيير التي لم يؤكدها الخادم بعد. الربط والتنعيم الصحيح داخل التطبيق ما زالا جزءاً مطلوباً قبل إصدار APK جديد.
6. يقبل الخادم الأوامر المتأخرة حتى 90 إطاراً. يعيد حساب العالم من سجل الإطار السابق للأمر. لا يستخدم تاريخ استلام HTTP بديلاً عن توقيت اللعب.
7. رسالة `ping` تتضمن `clientTime` ويعيد الخادم `pong` مع `serverTime` لقياس زمن الرحلة وتقدير ساعة الغرفة.
8. رسائل التفاوض الصوتي `voice` تتبع حقول الخدمة السابقة `enabled,call,seq,ack,signals` وترتبط بهوية الاتصال الحالي. تدفق الصوت نفسه عبر WebRTC. هذه الحزمة لا تثبت نجاح المحادثة الصوتية على أجهزة فعلية.

صاحب الغرفة هو من ينفّذ أوامر بدء الجولة وإعادتها. يجب استخدام أرقام طلبات فريدة حتى لا يعيد وصول الطلب نفسه تنفيذ إجراء سابق.

## التحقق

شملت الاختبارات أربع اتصالات WebSocket حقيقية بالخادم المحلي، ووصول أوامر متأخرة 180 ملّي ثانية، والاستعادة بعد قطع اتصال لاعب، ورفض انتحال الجلسة وصلاحيات المضيف. اختُبرت إعادة المحاكاة بعد وصول الأوامر متأخرة حتى 36 إطاراً ومطابقتها للمحاكاة التي استقبلت الأوامر في موعدها لفرق من 2 و3 و4 لاعبين.

هذه اختبارات محلية. ما زال مطلوباً قياس التأخير عند النشر ثم اختبار التطبيق على هواتف عبر شبكات مختلفة. لا تتضمن الحزمة تغييراً منشوراً إلى اللعبة الحالية.
